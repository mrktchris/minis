# Contributing to Taskbar Fighters

Thanks for wanting to make the fights better. Small, focused pull requests are the easiest to review and merge.

## Set up

```
git clone https://github.com/mrktchris/taskbar-fighters
cd taskbar-fighters
python -m pip install -r requirements.txt          # Pillow only
python -m unittest discover -s tests               # expect OK, ~11 skipped
```

On a Mac, also install `requirements-mac.txt` (once it exists). The macOS port is experimental.

Python 3.12 or newer is required. CI runs the suite on Windows and macOS, with Python 3.12 and 3.13.

## Ground rules

These are the privacy promises in [SECURITY.md](SECURITY.md), and a pull request that breaks any of them will not be
merged:

- **Read numbers, never content.** Detectors may read token counts, timestamps, tool-call states and process names.
  Never prompt or reply text, window titles, or file or project names.
- **No network.** The app makes no network calls.
- **Never touch the user's AI tools.** No hooks, status lines or config edits in Claude Code, Codex, Cursor or anything
  else.
- **Visual only.** Arena mode pretends to break windows. It must never move, close or send input to a real one.
- `stop` only stops processes it started and can prove are its own. Keep that ownership check.

## Add an AI program (a detector)

1. Add one row to `RULES` in `minis_core/sources.py`:

   ```python
   dict(source='myagent', program='My Agent', character='generic',
        exe=('myagent.exe',), cmd=('myagent', '@scope/myagent'))
   ```

   `exe` holds image names from the process table. `cmd` holds names matched against an interpreter's first
   arguments (`node`, `python`, `npx` and so on). On macOS, check `rules_for()` for the mac names.
2. Optionally add a short HUD name in `LABEL`.
3. Run the tests, then `python minis.py detect`. It shows whether your program is seen and how.

Not sure of the process name? Open a [new AI program request](../../issues/new?template=new_ai_program.yml) with what
Task Manager or `ps` shows.

## Add a character

1. Add a `Body(...)` and an `_c(...)` entry to `art/roster.py`. Copy an existing one and change the proportions,
   weapon, palette and signature moves (strike, special, super, ultimate).
2. Build the sheets with `python art/build_fighters.py --all --only <name>`. This writes `assets/<name>` and
   `assets_hd/<name>`.
3. Run `python -m unittest tests.test_art`.
4. The new character appears in the fighter select LOOK grid without further changes. Try it with
   `python minis.py skin <program> <name>`.

All art is generated by the rig in `art/` from pose data. Please do not commit art copied from asset packs: see
[docs/CREDITS.md](docs/CREDITS.md) for what was studied and how.

## Before you open a pull request

- `python -m unittest discover -s tests` passes.
- For a visual change, attach a GIF or PNG. `python tools/doc_images.py` renders the docs images offline with DEMO
  numbers. Please do not post screen captures of your whole desktop.
- Add a line to `CHANGELOG.md` under the next version.
- Keep the code style of the file you touch: short functions, comments that explain why.

## Reporting bugs

Use the [bug report form](../../issues/new?template=bug_report.yml) and paste `python minis.py status` and
`python minis.py detect`. Both print names and numbers only.
